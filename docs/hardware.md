# 设备与外设

[文档导航](README.md) · [首次运行](../QUICKSTART.md) · [排障](faq.md)

本页说明代码的接入范围，不代表所有同协议或同型号设备都已验证。SDK 推理芯片、ABI 和模型支持由交付版本确定，不从 App 的 minSdk 推断。

## Android 与通信

| 项目 | 当前范围 | 部署时核对 |
| --- | --- | --- |
| 客户端系统 | Android 5.0 / API 21+，targetSdk 35 | 原生依赖 ABI、厂商权限与窗口策略 |
| 本机 AIDL | API 27+ | 晨检 SDK 包名 `cc.huoyan.morningcheck` 与对应服务可用 |
| 本机 WS | API 21+，`ws://127.0.0.1:18087/` | SDK 后台服务已启动 |
| 局域网 WS | `ws://<SDK设备IP>:18087/` | 实际 IP、路由/AP 隔离、防火墙及 SDK 允许访问范围 |
| 现场语音 | Android TTS 和可用中文语音数据 | 引擎、音量及系统后台策略 |

自动通道只根据地址与系统版本决定；请求失败不等于可以无条件切换到另一台本机 SDK。局域网 SDK 可与客户端分机，但 SDK 机器仍需支持的硬件和授权。普通模拟器只能验证页面、协议和部分业务，不能据此判断原生 SDK 与外设兼容。

## 相机

支持系统 Camera2 与直接 USB UVC。需授予相机权限；USB 另需 USB Host/OTG、设备访问授权及足够供电。采集设备页分别选择身份/头部与手部相机，保存前观察实际预览，两种角色可以共用一台镜头。

工控机的 USB 镜头不一定由 Camera2 正常暴露。USB 枚举与旧系统相机别名发生变化时重新选择，不能按名称猜角色。多台同型号 USB 相机应确认各自连接，换端口后重新核对。

检查画面方向、镜像、焦距、曝光和检测框位置；USB 原始方向不能代表机器安装方向。避免扫码工具、厂商相机与其他 App 同时占用镜头。页面退出前台会释放采集。

## 测温

`TemperatureSource` 通过 `android-serialport` 访问已配置串口。初始路径 `/dev/ttyS4`、115200、被动上报，仅作项目默认值；实际端口和权限由设备厂商确认。

- 被动读取处理 `{36.65}` 形式的文本。
- 主动查询发送 `ConfigT` / `CalcT`，解析文本或 CT 返回帧。
- 海曼模块可发送 `*inside`、`*outside`、`*trigger`，收到本次 `success` 才保存模式；算法模式不等于主动/被动读取方式。

未保存确认记录时页面显示动态触发默认选项，只是界面初始值，不代表已经询问或修改模块。无确认、超时或串口错误按失败处理，不能仅凭字节写入成功认定模式已切换。

串口路径、波特率、供电、接线、距离和模块算法共同影响读数。25–26°C 可能是环境/目标或模式条件，不能一概当体温；按模块手册和实际原始回包排查。App 不修改系统节点权限，不应盲目使用 `su/chmod`。

## 补光

支持串口或 GPIO，具体输出由 `LightController` 持有。当前默认配置为串口 `/dev/ttyUSB0`、115200、8N1，字符指令 `A00101A0` 开灯、`A00100A0` 关灯；GPIO 默认 122、148，0 开、1 关。它们只适用于相应接线，其他设备须按厂商指令调整。

灯光管理可测试亮灭；现场晨检与选定员工后的人脸采集使用同一配置，离页、后台或采集停止时关闭。串口补光协议没有硬件确认，实际亮灭需目视检查。不要把“已发送”当作设备应答。

## 不在通用实现范围

当前未移植酒精检测仪、打印机或其他厂商专有硬件，记录上传也不是外设功能。首次部署按[测试指南](testing.md)记录具体通过的预览、身份、人脸学习、手部、测温和亮灭步骤，不把安装成功记成整机验收。

反馈时提供 Android/API、ABI、App/JAR/SDK/模型、外设型号、串口参数和脱敏错误原文。不要公开激活码、员工照片或完整设备序列号。
