# 常见问题

[文档导航](README.md) · [快速开始](../QUICKSTART.md) · [硬件](hardware.md) · [支持](../SUPPORT.md)

## 没有 SDK、激活码或外设，能先看什么

可构建 App、查看管理与设置页面，并运行不依赖设备的单元测试。身份识别、检测与人脸学习需要配套 SDK、模型和有效授权；真机温度与灯光必须用对应外设验证。未接设备时不伪造员工匹配、温度或检测完成。

## SDK 下载在浏览器报错

安装引导当前使用 HTTP 地址，浏览器的 HTTPS 页面下载策略可能拦截 HTTP 文件；不能仅把 `http` 改成 `https` 就认为解决。若服务域名的 HTTPS 证书不匹配，应由服务端配置证书，或联系火眼获取对应版本。App 下载失败与系统拒绝安装是两步不同问题，反馈错误原文及发生步骤。

## SDK 没有桌面图标，是否没装成功

晨检壳提供后台服务，不能用桌面图标判断。核对系统应用列表中的 `cc.huoyan.morningcheck`，再从 App 的 SDK 连接设置连接。壳进程启动恢复以实际配套版本为准；反复卸载会影响 SDK 自己的数据，不是通用恢复步骤。

## 本机或局域网连不上

晨检默认 WS 为 `ws://127.0.0.1:18087/`，远端把回环地址换成 SDK 机器的实际 IP；不要套用识物的 18086 或 `/ws`。API 27 及以上本机自动选择 AIDL，较早系统使用 WS。核对通道、服务、网络隔离、防火墙和 SDK 允许访问范围，保留连接错误码。

## 激活成功却暂时不能检测

激活回执成功与模型已准备好不同。初次激活、下载模型、证书和密钥均由 SDK 管理，App 按实际回执准入。保留当前激活结果并等待常规状态更新，不把成功提示当作 READY，也不要在结果未知时自动重复激活。

## 断网后是不是整个 App 都不能用

员工资料、本地记录和设置不依赖每次联网。已激活且模型、密钥及证书有效时能否离线识别，以 SDK 实际状态为准；首次激活、模型准备和业务云接口仍需网络。证书失效会影响身份、检测及学习，不能因此推定本地记录丢失。

## 有人脸框却提示未匹配员工

框来自当前图像中的人脸定位，身份仍由 SDK 识别回执决定。检查是否给当前员工在当前 SDK 录入过样本、员工是否启用、连接是否切到其他设备，以及图像质量。工号修改不应改变该员工的 SDK `person_id`；不要手改 ID 试图关联别人的人脸库。

## 人脸样本没有照片，是否可以删本地文件解决

App 使用 SDK `register.image_url` 与 `userDetail.items[]` 展示样本，照片原图由 SDK 管理。原图不可用与样本不存在不同；在录入页通过删除或清空操作处理，不能只删 App 缓存当作清掉 SDK 人脸。

## 温度不更新或切模式后读不到

先区分算法模式与串口读取方式，检查路径、波特率、权限、其他程序占用和模块原始回包。切换须收到 `success`；动态触发可能需要实际目标触发，不保证持续自主上报。主动模式的 `ConfigT/CalcT` 与被动文本也不能混用。详细边界见[测温说明](hardware.md#测温)。

## 首页统计与“异常记录”条数不同

首页按当前名册统计当天人数，同一员工按当天最新有效结果归类；记录列表保留每次检查。某员工先异常后正常，可以计为当天正常一人，同时仍留有较早的异常记录。记录筛选按采集快照与时间区间处理，翻页前先核对筛选条件。

## 为什么退出需要密码

现场晨检避免误退出，仅右下角退出入口进行密码验证。初始密码 `123456`，部署时应在系统设置修改；密码变更要求原密码。开启自动进入晨检后的开机跳转仍受系统/固件后台启动政策限制。

## 换包名、换签名或卸载会影响什么

包名变更应重新确认 SDK 接入登记；签名不兼容不能直接覆盖。卸载或清除 App 数据会删除本地员工、记录与照片，SDK 人脸库不会因此自动与新名册重新配对。不要在业务机器上把卸载当常规排障，升级要求见[版本兼容](version-compatibility.md)。

## 修改了 JAR 源码但 App 没变化

App 引用已提交的发行 JAR，不直接引用源码模块。先执行 `:huoyanClient:updateAppSdkJar`，再重新构建安装 App。只运行 `assembleDebug` 不会替换 JAR，版本与输出见[构建指南](build.md)。
